# Сервис уведомлений

Автор: Станислав Лисенков

## Что делает программа

Программа представляет собой учебный сервис рассылки уведомлений через различные каналы связи (`EmailNotifier`, `PushNotifier`), реализующие единый интерфейс `Notifier`. Отправка сообщений может выполняться через обычный диспетчер `Dispatch` (до первой ошибки) или защищённый диспетчер `SafeDispatch` (перехватывает паники и опрашивает все каналы до конца). При успешной отправке каждое сообщение сохраняется во внутренней истории соответствующего канала с префиксом его имени.

## Как запустить

Все команды выполняются из корневой папки модуля `student` (версия Go 1.22+):

```bash
# Форматирование и статическая проверка
gofmt -w practice/tasks.go cmd/notify/main.go
go vet ./...

# Запуск тестов
go test -v ./practice -run TestHomework
go test ./...

# Сборка и запуск демонстрационной программы
go build ./...
go run ./cmd/notify
```

## Проверенные случаи

1. **Успех**: Создали Email с адресом и Push с `DeviceID`, отправили текст `"Заказ готов"` через `Dispatch`. Ошибок нет, в истории обоих каналов появились сообщения `"[email] Заказ готов"` и `"[push] Заказ готов"`.
2. **Пустой текст**: Отправили пустую строку `""` через `Dispatch`. Вернулась ошибка, которую мы проверили через `errors.Is(err, practice.ErrEmptyMessage)`. Истории каналов не изменились.
3. **Нет настройки**: Создали Push без `DeviceID` и попробовали отправить текст. Вернулась ошибка, из которой с помощью `errors.As` достали структуру `*SendError` с полями `Channel: "push"` и `Reason: "не задан device id"`. История осталась пустой.
4. **Сломанная реализация**: Запустили `SafeDispatch` со сломанным каналом `BrokenNotifier` и обычным `PushNotifier`. Первый канал вызвал панику, но программа не упала — ошибка вернулась в общем списке (проверяется через `errors.Is(err, practice.ErrNotifierPanic)`). Следующий за ним `PushNotifier` нормально отработал и сохранил сообщение `"[push] Важное уведомление"`.

## Обработка ошибок

- **Чем отличаются `Dispatch` и `SafeDispatch`**:
  - `Dispatch` останавливается на первой же ошибке и возвращает её. Если в канале случится паника, программа упадёт.
  - `SafeDispatch` проходит по всем каналам до конца, даже если где-то произошла ошибка или паника, и возвращает список всех возникших ошибок (`[]error`).
- **Где используются `errors.Is` и `errors.As`**:
  - `errors.Is` используется в `main.go`, чтобы узнать конкретную причину ошибки внутри обёртки: пустое сообщение (`ErrEmptyMessage`) или паника канала (`ErrNotifierPanic`).
  - `errors.As` используется, чтобы достать из обёрнутой ошибки структуру `*SendError` и прочитать её поля `Channel` и `Reason`.
- **Почему `recover` находится в отдельной функции `SafeSend`**:
  - `recover` останавливает панику только в той функции, где он вызван через `defer`. Если бы `recover` стоял прямо в `SafeDispatch`, то при панике первого канала прервался бы весь цикл, и остальные каналы ничего бы не получили. А внутри `SafeSend` паника ловится в рамках одного канала, превращается в обычную ошибку, и цикл в `SafeDispatch` спокойно идёт дальше.
